Design loops, not prompts

Loop engineering: design loops that prompt agents

Seed tweet · source: W26 skill S=0.9

The claim

The scarce skill is no longer a clever one-shot prompt. It is a loop: generate, critique, test, repair, stop. People who design those loops outperform people who chat. “Loop engineering” is a good name for that craft when it means harness design, not buzzword cosplay.

Prompts still matter. They matter as components inside a process that can fail closed. Without structure, “agentic” means expensive freeform conversation with a model that never has to prove anything.

Why loops beat monologues

A monologue asks the model to be right the first time. A loop assumes partial failure and budgets for recovery. That matches how real engineering already works: compile, test, review, patch. The difference is that the loop can now include model steps as first-class stages, not as a human’s private thinking.

The people who look magically productive with agents usually own better loops. They have scripts, checklists, eval hooks, and file layouts that re-enter context every run. The chat transcript is the thin surface of a thicker process.

The failure modes of “loop” talk

Loops burn tokens. Without stop rules they can produce confident slop that still needs human cleanup. Without external checks they can converge on self-consistency rather than truth. Without ownership they become a fashion name for “keep regenerating until the vibes improve.”

There is also a labor story that is easy to smuggle in. Each new abstraction ladder — tools, prompts, meta-loops — can be sold as the next reason developers still matter, right until the ladder moves again. Treat loop design as real systems work. Do not treat it as a managed retreat narrative dressed as empowerment.

What a real loop looks like

Operationalize loops as harnesses, not slogans:

  • Inputs: task brief, constraints, and acceptance criteria
  • Generate step with bounded scope
  • Critique step that can fail the candidate
  • Test or eval step outside the model’s self-score when possible
  • Repair step with a max iteration count
  • Stop rule that is explicit and logged

If the loop cannot fail a check, it cannot improve. If it cannot stop, it is a spend curve, not a process. Prefer scripts and project configs over memory of “how we usually do it.”

Closing

Design loops that prompt agents. Do not collect prompts that pretend to be loops. The craft is process design with machine steps inside it: where generation starts, how judgment enters, what counts as done, and when the system must refuse to continue.
