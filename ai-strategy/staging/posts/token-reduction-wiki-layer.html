External memory beats re-sending the corpus

Token-reduction / wiki-layer memory systems

Seed tweet · source: W26 skill S=0.9

The claim

Wiki-layer memory systems claim large token savings by turning raw notes into linked markdown. The idea is real: durable external memory beats re-sending a corpus every time.

Verify savings on your workload. Measure quality of links and update cost, not just token counts on a demo path.

The problem they are solving

Agents that must “remember” a project often do it the expensive way. Each session reloads the same long briefs, meeting notes, and design docs into context. The model re-reads what a filesystem already holds. Tokens climb. Attention spreads thin. Important constraints get truncated first.

A wiki layer inverts that pattern. Raw material is distilled into short, linked pages: decisions, owners, current state, open risks. The agent loads a map and a few pages, not the archive. Humans can also read and correct the map. That dual use is the point. External memory is not only a compression trick. It is a shared working surface.

Where demos lie

Token-reduction claims often measure an idealized path: a clean corpus, a single query style, a freshly built index. Your week is messier. Notes conflict. Names change. Two pages say opposite things about the same API. A 90% token cut on a demo path can become a 20% cut — or a quality loss — once the wiki falls behind the world.

The second lie is treating tokens as the only cost. Writing and maintaining the wiki takes human or agent time. Bad links cost more than the tokens they save when the agent acts on stale structure. A system that is cheap to query and expensive to keep true is not free. It has moved the bill to operations.

What to measure

Before packaging a wiki-layer technique as standard practice, run it against your real tasks for long enough that pages go stale.

  • Token use per completed task on your mix of work, not on a single showcase query.
  • Answer quality under audit against source documents the wiki claims to summarize.
  • Link integrity: broken, circular, and contradictory links found per week.
  • Update cost: minutes to absorb a decision change into the right pages.
  • Cold-start cost: how long a new agent or person needs before the wiki helps more than it confuses.

If token counts fall while audit quality and update cost worsen, you have built a lossy cache with good marketing.

Design rules that keep the idea honest

Prefer short canonical pages over giant dumps. Put owners and “last verified” dates on pages that drive action. Make contradiction visible instead of averaging it away. Give the agent a retrieval path back to primary sources when the wiki is thin. Never let the wiki become the only place truth is allowed to live.

Compression without a path back to evidence is just confident amnesia.

Closing

External memory beats re-sending the corpus. That is sound systems thinking. Wiki-layer tools are one way to do it. Trust them after they survive your workload, your stale notes, and your update habits — not after a single chart of token savings on a polished path.
