Short verified cycles beat monologue coding

Feedback-loop / iterative agent development workflow

Seed tweet · source: W26 skill S=0.9

The claim

Iterative feedback-driven development is the practical core of agentic coding. The winning pattern is short cycles with verifiable checks, not long monologues to a model. Require tests, diffs, and acceptance criteria in the loop. If the loop cannot fail a check, it cannot improve.

Builders keep rediscovering this under new names: plan optimizers, self-scoring skills, “build in loops.” The durable part is not the brand. It is the closed circuit between attempt and evidence.

Why monologues fail

A long single-shot request asks the model to invent architecture, implement, and self-bless in one breath. Errors compound. Context fills with confident partial work. By the time you read the end, you are debugging a novel rather than reviewing a change.

Short cycles reverse that. You force a smaller unit of work, force a check, then decide whether to continue. The human stays in the authority seat for “good enough,” even when the model does most of the typing. That is not romantic craft nostalgia. It is control design.

Self-scoring is not verification

A common failure mode is the self-referential loop: the same model rewrites a plan, scores its own rewrite, sees prior scores, and stops when it can no longer improve by its own metric. Convergence feels like quality. It may only be self-consistency.

External criteria matter. Prefer tests that already exist, linters, typechecks, acceptance scripts, or a second model that never saw the earlier self-scores. Prefer a human glance at a diff against a written definition of done. Endogenous stop rules package false confidence as best practice.

What to operationalize

Use a loop that a stranger could run from your repo:

  • Write acceptance criteria before generation
  • Generate the smallest change that could meet them
  • Run checks the model did not invent for itself
  • Read the failing evidence, not only the model’s story about it
  • Repair with a max iteration count
  • Stop when criteria pass or when the stop budget is spent

Package that as a skill or script if you want reuse. Do not package “keep iterating until it feels done.” The skill is valuable only if the failure path is real.

Closing

Agentic coding rewards people who shrink the cycle and harden the check. Monologue coding rewards people who enjoy watching tokens. Choose the first if you care about software that survives contact with a test runner.
